## Phase Goal

**As a** developer, **I want to** have the on-device logic (syllable counting, keepsake naming, the mock backend, and the full AppModel arc) pinned by fast, deterministic unit tests, **so that** regressions are caught without a human at a simulator.

> This restates the ROADMAP Phase 2 **Goal:** line and adds nothing (see 02-01-PLAN.md).

This plan closes the phase's expected finding, the late-poll race, under fix-as-we-go. It leads with the ROADMAP's named case (leaving mid-poll) as a red-then-green tracer slice. It then expands to the action-task writers, where research found the race is wider than the poll loops (RESEARCH Pitfall 2).

<objective>
Reproduce the late-poll race deterministically and fix it with D-08's two layers.

First, a red run: a gated poll response released after `leave()` brings the session back. That red run is recorded. Then `Task.isCancelled` plus an epoch counter turn it green. Next, the action tasks: a late submit, a late enter, a stale enter after begin-again, and a late resume. Each is written red against the poll-only fix and recorded. Then `apply(_:epoch:)` and the guards on every action write site turn them green.

Purpose: IOST-04's "leaving mid-poll" clause (ROADMAP success criterion 4), D-08, D-09, and D-10. The red evidence feeds Phase 4's FIX-01 ledger.
Output: one new test file and one fixed app file, in four commits: red, green, red, green.

Depends on plan 02-01 (FakeBackend, TestSupport, task handles, and the shared simulator; see the wave note in 02-01-PLAN.md).
</objective>
