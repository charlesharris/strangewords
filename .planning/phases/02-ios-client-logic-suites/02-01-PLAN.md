## Phase Goal

**As a** developer, **I want to** have the on-device logic (syllable counting, keepsake naming, the mock backend, and the full AppModel arc) pinned by fast, deterministic unit tests, **so that** regressions are caught without a human at a simulator.

> This restates the ROADMAP Phase 2 **Goal:** line and adds nothing. That line is not written as a canonical user story; run `/gsd-mvp-phase 2` if you want it formalized in ROADMAP.md.

This plan is the phase's tracer. It proves the riskiest piece of the architecture end to end: injected seams, a gated fake backend, and deterministic AppModel tests running through the Phase 1 harness. It then expands that slice to the full arc (IOST-04) and to defaults-preservation proof for the seams (IOST-05).

<objective>
Wire ONE AppModel test end to end. The path runs from the injectable TokenStore and the defaulted init parameters, through a gated FakeBackend, to `begin()` landing in `.composing`, all green via `scripts/test-ios.sh`. Then expand to the full state-machine arc with error paths. Finally, land the APIClient base/session seam, defaults-preservation tests, and the `UserDefaults.standard` hygiene guard.

Purpose: IOST-04 and IOST-05 (except the LocalBackend delay seam, which is plan 02-03), plus ROADMAP Phase 2 success criteria 1, 4, and 5. Plan 02-02 builds its red-first stale-writer tests on the FakeBackend, task handles, and test support this plan creates.
Output: four app files with seams (behavior unchanged) and four test files. Each task ends in a commit.

**Wave note.** All four Phase 2 plans run in sequence (01 → 02 → 03 → 04), even though 02-03 and 02-04 share no files with this plan. Every plan proves itself through `scripts/test-ios.sh`, which boots the single pinned "iPhone 16" simulator and shuts it down on exit. The harness has no lock against concurrent runs (STATE.md Phase 4 carry-over; Phase 1 EDGE-HARN-03), so parallel plans would kill each other's runs.

**Stale-writer protection is out of scope here.** Plan 02-02 must write its regression tests red against the unprotected AppModel first (D-10). This plan therefore keeps every post-await write in AppModel exactly as it is today.
</objective>

D. ios/StrangewordsTests/FakeBackend.swift (new; D-05; RESEARCH Pattern 3 with all four of its "Required refinements"):
   - `actor FakeBackend: Backend` and `enum Kind: Equatable, Sendable { case enter, waiting, getSession, submitLine, leave, dismiss }`.
   - `final class Pending: @unchecked Sendable` holds `kind`, plus `id`, `token`, `line`, `text`, and `idemKey` as optionals, and a `CheckedContinuation<Any, Error>`. `resolve(_ value: Any)` and `fail(_ error: Error)` resume the continuation exactly once: a lock-protected flag turns any second resume into a no-op that records an `Issue`, instead of a trap.
   - `nonisolated let arrivals: AsyncStream<Pending>`, fed by a stored stream continuation, so arrival order is FIFO.
   - enter, waiting, getSession, and submitLine each append their kind to an internal call log, then suspend in `withCheckedThrowingContinuation` and yield the Pending into arrivals.
     - The suspension deliberately ignores cancellation of the calling task. It models a response the network has already delivered, which is exactly the window plan 02-02's stale-writer tests reproduce.
     - Each method casts the resolved value to its own return type. A value of the wrong type records an `Issue` and throws, so the host app does not crash.
   - leave and dismiss append to the call log and return immediately; they never park (RESEARCH Pitfall 6).
   - `func recordedCalls() -> [Kind]`.
   - `func drain()` fails every still-open Pending with `CancellationError()`. Cleanup relies on this (RESEARCH Pitfall 7).
