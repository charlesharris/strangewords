<objective>
Ship the robot poet in the app: a quiet gear on the Threshold opens a sheet with one switch, default OFF ("write with the robot poet"). When it is on, begin() tells the server allowBot true, the waiting room says so softly, and any session with the robot poet carries a persistent named-presence chip in Compose and Reveal, with honest their-turn copy. Every wire change is mirrored in Models, Backend, APIClient and LocalBackend.

Locked decisions implemented here: D-01 strict opt-in, default OFF (an absent preference reads false; nothing nudges); D-02 a quiet gear on the Threshold opening a minimal sheet with the one toggle, persisted in a UserDefaults sibling of TokenStore (CA92.1 already declared in PrivacyInfo.xcprivacy); D-04 named presence for the whole session, rendered only from the server's partnerIsBot. CONTEXT.md numbers these decisions 1, 2 and 4, cited here as D-01, D-02, D-04. D-03 and D-05 are server-side (Plan 01).

Purpose: the client half of the phase goal. The wire contract it mirrors (request `allowBot`, view `partnerIsBot` with omitempty) was proven end to end by Plan 01's tracer.
Output: SettingsStore, the AppModel opt-in seam, the contract mirror plus the LocalBackend arc, SettingsView, PartnerPresence, edits to Threshold/Waiting/Compose/Reveal, and Swift Testing suites proving all of it, run headlessly with scripts/test-ios.sh.

Scope (user's minimal-launch directive): the sheet ships exactly the UI-SPEC's one row in a VStack, with no extra scaffolding. The one-time VoiceOver announcement is a single line in ComposeView. Visual and VoiceOver behaviour is recorded as backstop truths for the deferred manual UAT rather than as tasks. There is no XCUITest (out of scope per REQUIREMENTS.md).

Planner assumption (UI-SPEC "iPad regular width", unresolved): on iPad the system presents the sheet as a form sheet and ignores detents. Constraining the content with `.frame(maxWidth: 480)` is assumed to read correctly. This is not exercised by any simulator run (portrait-only app, no UI automation) and is surfaced for the manual UAT pass. Nothing in this plan depends on it.

Wave note: this plan runs after Plan 01 for tracer-first ordering. It has no file overlap with Plan 01. Its three tasks run sequentially because scripts/test-ios.sh drives one pinned simulator and has no concurrent-run lock.
</objective>
