<objective>
Ship the robot poet's UI in the app. A quiet gear on the Threshold opens a sheet with one switch, default OFF ("write with the robot poet"). When the switch is on, the waiting room says so softly, and any session with the robot poet carries a persistent named-presence chip in Compose and Reveal, with honest their-turn copy.

Locked decisions implemented here:
- D-01 strict opt-in, default OFF: the switch shows OFF on a fresh install, and nothing nudges.
- D-02: a quiet gear on the Threshold opening a minimal sheet with the one toggle, bound to Plan 02's persisted AppModel.allowBot.
- D-04: named presence for the whole session, rendered only from the server's partnerIsBot.

CONTEXT.md numbers these decisions 1, 2 and 4, cited here as D-01, D-02 and D-04. D-03 and D-05 are server-side (Plan 01). D-01's wire half and D-02's persistence half are Plan 02.

Purpose: the visible half of the phase goal. Plan 02 supplies everything this UI reads (AppModel.allowBot, SessionView.partnerIsBot, and the LocalBackend wait-then-robot-poet arc used for mock-mode UAT).
Output: SettingsView, PartnerPresence, edits to Threshold, Waiting, Compose and Reveal, and the PartnerPresenceTests suite, run headlessly with scripts/test-ios.sh.

Split note: this plan is the former Task 3 of 05-02, moved unchanged when the checker's file budget split that plan. No scope was added or removed.

Scope (user's minimal-launch directive): the sheet ships exactly the UI-SPEC's one row in a VStack, with no extra scaffolding. The one-time VoiceOver announcement is a single line in ComposeView. Visual and VoiceOver behaviour is recorded as backstop truths for the deferred manual UAT rather than as tasks. There is no XCUITest (out of scope per REQUIREMENTS.md).

Planner assumption (UI-SPEC "iPad regular width", unresolved): on iPad the system presents the sheet as a form sheet and ignores detents. Constraining the content with `.frame(maxWidth: 480)` is assumed to read correctly. No simulator run exercises this (portrait-only app, no UI automation), so it is surfaced for the manual UAT pass. Nothing in this plan depends on it.

Wave note: this plan runs after Plan 02 because it compiles against AppModel.allowBot and SessionView.partnerIsBot. It has no file overlap with Plan 01 or Plan 02.
</objective>
