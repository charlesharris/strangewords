# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5: Opt-In Robot Poet Collaboration. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Platform: native SwiftUI, iOS 17+, iPhone + iPad, portrait-only, fullscreen. Units are points (pt), written "px" only where the checker template expects it.
> Scope: exactly three surfaces. (1) Settings gear + sheet on the Threshold. (2) The persistent named-presence caption in Compose and Reveal. (3) The soft opted-in line in the waiting room. Nothing else on screen changes.

## Color

All colors come from the active theme's `Palette` (3 themes x 3 times of day = 9 palettes; Nature, SciFi, Fantasy). **Do not hardcode hex values.** The tokens below resolve per theme.

| Role | Palette token | Usage in this phase |
|------|---------------|---------------------|
| Dominant (60%) | `skyTop` / `skyBottom` scene (behind everything) and the sheet's `skyBottom` background | Scene and sheet surface |
| Secondary (30%) | `onAccent` at 0.6 opacity as a backing fill (same recipe family as the ritual capsule, which uses 0.85) | Gear backing circle, caption chip backing, settings row card |
| Accent (10%) | `accent` | See reserved list |
| Text | `ink` (full opacity on chips and the row; 0.85 for the helper) | Caption chip text, toggle label, title, helper |
| Hairline | `ink` at 0.15 | Settings row card stroke (1pt) |
| Destructive | none | No destructive action in this phase |

Accent reserved for: (1) the "on" tint of the single robot-poet switch (`.tint(palette.accent)`). Nothing else. The gear, the caption chip and the waiting soft line must NOT use accent.

Why the `onAccent` 0.6 backing is mandatory (contrast): `onAccent` has the opposite luminance of `ink` in every palette, so ink-on-backing stays legible even where the scene itself fights `ink`. Verified by inspection against the palettes: SciFi morning has a dark `skyTop` (0x243A6E) with a dark `ink` (0x14263F), and the Reveal phase darkens day scenes with the dusk overlay (`sceneDepth` 0.70); bare `ink` or `secondary` text at the top of the screen would fall under 4.5:1 in both cases. With the backing, text and glyph clear 4.5:1 (text) and 3:1 (glyph) in all nine palettes by the luminance estimates: worst case SciFi morning ~6:1, Nature morning ~10:1, night palettes >10:1. Do not use `palette.secondary` for any Phase 5 text (Nature morning `secondary` over `skyTop` measures about 2.8:1).

Known limitation, accepted: the switch's on-state track (`accent`) is below 3:1 against the sheet surface in the light Nature palette (about 2.3:1). State is not conveyed by color alone: the thumb position and the VoiceOver value ("on"/"off") carry it, and the system's "On/Off Labels" accessibility option is honored automatically by `Toggle`. Do not override the toggle style.

## Surface 1 — Settings gear and sheet (ThresholdView)

### Gear affordance
- Placement: **top-leading** of the Threshold, as an `.overlay(alignment: .topLeading)` on `ThresholdView`'s root `VStack`. Dev chips occupy `.topTrailing` at the `RootView` level when `Dev.showControls` is true, so top-leading never collides with them on any supported width (chips are about 120pt wide, right-aligned). Do not place the gear top-trailing.
- Geometry: 44x44pt hit area; `Image(systemName: "gearshape")` at `.font(.system(size: 18, weight: .regular))` (SF Symbol scaled by the system, not a Theme token), centered in a 36pt backing `Circle` filled `palette.onAccent.opacity(0.6)`, glyph tinted `palette.ink.opacity(0.8)`. The hit area is the 44pt frame (`.contentShape(Rectangle())`).
- Horizontal alignment: the 44pt hit area is offset `x: -14` from the content edge, so the glyph's visual left edge sits near the 28pt content margin. Top inset: 8pt below the top safe area (`.padding(.top, 8)`).
- Visibility: shown only in `.threshold` (it lives inside `ThresholdView`, so it is automatically absent in waiting, compose, reveal, dissolving, dissolved). Never in the middle of a poem.
- Press state: opacity 0.6 while pressed, `.easeOut(duration: 0.15)`. No scale effect (the ritual scale is reserved for ritual buttons). Use a plain `ButtonStyle`, not `.ritual`, so it stays quieter than "begin".
- Accessibility: `.accessibilityLabel("Settings")`, `.accessibilityHint("Opens preferences, including writing with the robot poet.")`. Hit target >= 44x44. The gear is first in VoiceOver reading order (top-leading) and "begin" remains the last, primary action.
- Reduce Motion: the gear has no motion beyond the 0.15s opacity press response, which is allowed.

### Sheet
- Presentation: `.sheet(isPresented: $showSettings)` owned by `ThresholdView` (`@State private var showSettings = false`; sheet-open is view-local UI state, not `AppModel` state).
- Detents: `.presentationDetents([.medium, .large])` (research proposed `.medium`; `.large` is added so very large Dynamic Type sizes and the VoiceOver rotor are never clipped). `.presentationDragIndicator(.visible)`. On iPad (regular width) the system renders a form sheet and ignores detents; constrain content with `.frame(maxWidth: 480)` centered so the row does not stretch.
- Background: `.presentationBackground(palette.skyBottom)` (opaque, not material). Reason: a material over three procedurally different scenes (including the dithered pixel scenes) is unpredictable; an opaque palette surface keeps contrast fixed across all 9 palettes.
- Environment: the sheet content MUST be re-injected explicitly: `.environment(\.palette, palette)`, `.environment(\.sceneTheme, theme)`, `.environment(model)` and `.preferredColorScheme(palette.isDark ? .dark : .light)`. Do not rely on inheritance (research assumption A2 is unverified).
- Layout (top to bottom, inside a `ScrollView`, horizontal padding 24, top 32, bottom 48):
  1. Header row: title `Text("settings")` in `Theme.poem(20)`, `palette.ink`, centered, `.accessibilityAddTraits(.isHeader)`. A trailing "done" button on the same row (see below).
  2. 24pt gap.
  3. Row card (the only row this phase): `RoundedRectangle(cornerRadius: 16)` filled `palette.onAccent.opacity(0.6)`, stroked `palette.ink.opacity(0.15)` 1pt, inner padding 16, minimum height 56.
  4. Rows are children of a `VStack(spacing: 16)` so later rows append without layout changes. No section headers, no dividers, no footer.
- Row content: a single `Toggle(isOn: $model.allowBot)` whose label is a `VStack(alignment: .leading, spacing: 4)`:
  - Primary: `Text("write with the robot poet")` in `Theme.chrome`, `palette.ink`.
  - Helper: `Text("if no one else arrives after a little while, a robot poet — software on our server, not a person — can write with you, and you'll always be told.")` in `Theme.label`, `palette.ink.opacity(0.85)`.
  - `.tint(palette.accent)`; default OFF. The toggle is the whole row's tap target (the label is inside the `Toggle`, so tapping the text also toggles).
- "done" button: top-trailing in the header row, `Theme.chrome`, `palette.ink`, plain button style, 44x44 minimum hit area. Calls `dismiss()`. It exists so Voice Control and Switch Control users have a visible dismissal; drag-down and tap-outside also dismiss. Do not use `.ritual`.
- Write-through: toggling writes immediately to `AppModel.allowBot` (which persists via `SettingsStore`). There is no Save button and no confirmation. The new value applies to the next `begin()`.
- Haptics: none from the app (the system switch supplies its own). Do not call `Haptics.soft()` here; that vocabulary is reserved for deliberate ritual acts.
- Accessibility: `Toggle` is announced as "Write with the robot poet, switch button, off". The helper is part of the combined element via `.accessibilityElement(children: .combine)` on the label; it is read as the toggle's description. No custom `accessibilityValue`.
- Reduce Motion: sheet transition is the system's (respects Reduce Motion); the app adds no custom motion inside the sheet.

## Surface 2 — Named-presence caption (ComposeView and RevealView)

Shown only when `session.partnerIsBot == true`. Absent (not just hidden: the view is not in the hierarchy, and no spacing is reserved) in every human-human session. It is a persistent label: present in the your-turn and their-turn states of Compose, and in Reveal. It does not animate, pulse, or dismiss.

### Component
A `PartnerPresence` chip: a single `Text` in `Theme.label`, `palette.ink`, on a `Capsule` filled `palette.onAccent.opacity(0.6)`; padding 4pt vertical, 12pt horizontal; no stroke, no glyph. It is deliberately smaller and quieter than the ritual buttons (no 0.85 backing, no hairline) but is never lower contrast than body text.

### Placement
- **Compose:** first child of the existing `VStack(spacing: 28)`, before `Spacer(minLength: 24)`, aligned **leading** (`.frame(maxWidth: .infinity, alignment: .leading)`), with `.padding(.top, 8)`. In layout, not an overlay, so the poem lines can never run under it on a short screen with the keyboard open.
- **Reveal:** first child of the existing `VStack(spacing: 30)`, before the first `Spacer()`, same leading alignment and top padding. The poem stays vertically centered by the existing spacers. It sits at the top, away from the dusk-darkened bottom, and the chip backing keeps it legible under the Reveal depth overlay.
- Leading alignment is intentional: it reuses the "quiet chrome" top-leading slot the gear uses on the Threshold, and it keeps clear of the dev chips (top-trailing) in `SW_DEV=1` builds. Do not center it and do not move it top-trailing.

### Copy (from a pure function)
`PartnerPresence.caption(partnerIsBot:finished:) -> String?` (exact signature is the planner's call; the contract is the strings and the nil case):

| Context | Return |
|---------|--------|
| `partnerIsBot == false` | `nil` (no chip rendered) |
| Compose, `partnerIsBot == true` | `"writing with the robot poet"` |
| Reveal, `partnerIsBot == true` | `"written with the robot poet"` |

VoiceOver label for the chip (separate from the visible text, adds the "it is software" fact): `"Your partner is the robot poet, software on our server, not a person."` The chip is one accessibility element (`.accessibilityElement(children: .ignore)` + explicit label), reading order first on the screen.

### Companion copy change in Compose (their-turn state, bot partner only)
The existing their-turn copy promises a push that does not exist for bot turns. When `partnerIsBot`, replace the two lines:

| Element | Human partner (unchanged) | Bot partner |
|---------|---------------------------|-------------|
| Primary (`Theme.chrome`, `palette.secondary`) | `the stranger is with the poem now` | `the robot poet is with the poem now` |
| Secondary (`Theme.label`, `palette.secondary.opacity(0.8)`) | `it's fine to put this down — you'll be told when there's a line for you` | `its line will be here in a moment` |
| VoiceOver label | `Waiting for the stranger to write their line.` | `Waiting for the robot poet to write its line.` |

These two lines keep the existing `secondary` styling to stay consistent with the surrounding Compose screen (they are existing text and are outside the scope of the contrast rule above). The caption chip, not these lines, is the carrier of the disclosure.

### Announcement
On first appearance of `ComposeView` with `partnerIsBot == true`, post a single VoiceOver announcement (`AccessibilityNotification.Announcement("You're now writing with the robot poet.").post()`), once per session, so a screen-reader user who was in the waiting room is told at the moment the partner changes. No visual toast, no extra haptic (`Haptics.arrival()` already fires on match; leave it).

### Motion and Dynamic Type
- Arrives with the existing 0.6s root phase cross-fade (`.transition(.opacity)`); no separate animation. Under Reduce Motion there is nothing to remove.
- Wraps to multiple lines at large Dynamic Type; the capsule becomes a rounded block (`Capsule` still fine to ~2 lines; if the chip exceeds 2 lines at accessibility sizes, switch the backing shape to `RoundedRectangle(cornerRadius: 16)`).

## Surface 3 — Waiting-room acknowledgement (WaitingView)

Rule: a soft second line, present **only** when `model.allowBot == true` AND the view is the real waiting state (`connecting == false`). Absent for default-OFF users (their waiting room is byte-for-byte unchanged) and absent during `stepping in…`.

| Property | Value |
|----------|-------|
| Position | Directly under the existing `no one else is here just yet` line, inside the same centered `VStack`, 12pt below it (use `VStack(spacing: 12)` wrapping the two texts; keep the outer `spacing: 36`) |
| Typography | `Theme.label` (13, Regular), `palette.secondary.opacity(0.8)`, centered, wraps freely |
| Copy | `if no one comes, the robot poet may keep you company` |
| Timing | Shown from the first frame of `.waiting`; it is not revealed on a timer. Reason: it states a standing fact about the user's own setting, needs no timer state (views are pure functions of model state), and the user is never surprised by the swap |
| Motion | None added. It appears with the existing 0.6s phase cross-fade |
| Accessibility | The existing combined label becomes `"Waiting for a stranger to arrive. If no one comes, the robot poet may keep you company."` when `allowBot`; unchanged otherwise |

The `step back out` button, the breathing dot (already motion-light and `accessibilityHidden`), and all other waiting behavior are unchanged. The waiting line never says a time ("25 seconds") and never names the window. Settings cannot change while waiting (the gear exists only on the Threshold), so there is no state where the line and the actual `allowBot` sent at `begin()` disagree. `resume()` after a relaunch re-reads `AppModel.allowBot` from the store, so the line is consistent after resume too.

Contrast note: this line uses `palette.secondary`, same as the existing waiting copy, because it sits in the clear core of the waiting screen (`sceneDepth` 0 in `.waiting`), alongside text it must match. It is supplementary; the disclosure obligation is carried by the settings helper and the caption.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None added this phase. The existing `begin` CTA is unchanged. The only new interactive control is the switch: `write with the robot poet` |
| Settings title | `settings` |
| Settings helper | `if no one else arrives after a little while, a robot poet — software on our server, not a person — can write with you, and you'll always be told.` |
| Sheet dismiss | `done` |
| Compose caption (bot) | `writing with the robot poet` |
| Reveal caption (bot) | `written with the robot poet` |
| Compose their-turn (bot) | `the robot poet is with the poem now` / `its line will be here in a moment` |
| Waiting soft line (opted in) | `if no one comes, the robot poet may keep you company` |
| Empty state heading / body | Not applicable: no list or collection is introduced. (The waiting room is the app's existing "no one here yet" state; its copy is unchanged and gains only the soft line above.) |
| Error state | None new. The settings write cannot fail (local `UserDefaults`). Match/transport errors keep their existing copy (`Couldn't reach the quiet room`, etc.). Do not add a robot-specific error string; a failed bot fallback is indistinguishable from "no one came" to the user and routes through the existing `noOneCame` farewell |
| Destructive confirmation | None. No destructive action exists in this phase. Turning the switch off needs no confirmation; the default experience is humans-only |

Voice rules for this phase: always say `the robot poet` (never "bot", "AI", "assistant", "algorithm", "chatbot"); always describe it as software or by name, never as a person or "someone"; never "matched with", "queue", "searching", or any phrasing implying a pool of waiting robots. The disclosure must never be softened or removed by a later theme or copy pass: the caption is a persistent contract, not decoration.
