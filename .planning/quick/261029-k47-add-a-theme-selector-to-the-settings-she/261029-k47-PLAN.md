<objective>
Let production users choose the app's scenery. Nature, Sci-Fi and Fantasy are all already registered in `Themes.all`, but today a real install can only ever see Nature: the default is `all[0]`, and the only ways to switch are the dev-only `SW_FORCE_THEME` and the dev cycle chip. This plan adds a quiet "scenery" row to the settings sheet, persists the choice as a device preference beside `pref.allowBot`, and feeds it into RootView's active theme both at launch and live on change. Dev forcing keeps working.

Design choices, made at Claude's discretion. This quick task has no UI-SPEC, so this plan serves as the copy and layout contract and follows the Phase 5 settings-sheet conventions (`05-UI-SPEC.md` Surface 1):
- **A vertical list of option rows, not a segmented control.** A system segmented picker renders its labels in the system font, which ignores the Theme tokens, and its tint fights the palette. Three plain rows (glyph + name, 44pt minimum) inside the same card recipe as the robot-poet row (onAccent 0.6 fill, ink 0.15 hairline, radius 16, padding 16, min height 56) wrap cleanly at accessibility Dynamic Type sizes. The selected state is a glyph shape plus the `.isSelected` trait, never color alone. The glyph is ink, not accent, because Phase 5 keeps accent for the switch.
- **Copy: "scenery" / "the world your poem is written in. only you see it."** The visible word is "scenery", not the engineering word "theme". The helper states a true privacy fact: the choice is local and the partner sees their own. Option labels are each theme's existing lowercase `name` ("nature", "sci-fi", "fantasy"), so a theme added to the registry later appears automatically.
- **Row order: robot poet first, scenery second.** The rows live in the existing `VStack(spacing: 16)` "so later rows append without a redesign". The robot-poet disclosure row stays first and unchanged.
- **Precedence: dev chip > SW_FORCE_THEME > stored choice > nature.** `SW_FORCE_THEME` still wins over the stored choice, as required. The chip is a session-only override that never persists. `run.sh` sets `SW_DEV=1`, so the chips appear in every dev session. To keep manual testing honest there, a settings pick clears the chip override (not `SW_FORCE_THEME`), so a tester who touched the chip still sees the pick take effect.
- **The stored value is a theme id string under `pref.theme`.** An absent key means Nature. AppModel normalizes unknown ids to Nature in memory and never rewrites the key at init.
