<objective>
Make the return key in Compose offer the line instead of inserting a newline. Right now the Compose input is a `TextField(..., axis: .vertical)`, so return puts a `\n` into `AppModel.draft` and the user sees a two-line draft. After this change:
- Return runs the same action as the "offer this line" button when the draft is valid.
- Return does nothing when the draft is blank, while a line is in flight, or on the partner's turn.
- Line breaks can never be typed or pasted into the draft.
- All of this is pinned by tests that run without UI automation.

Premise correction (checked against the code, not taken on trust): the item says the server would reject a newline through CleanLine's control-character rule. It doesn't. `sessions.CleanLine` (server/internal/sessions/validate.go) and its mirror `LocalBackend.cleanLine` skip `\n`, `\r` and `\t` in the control check and collapse every whitespace run into one space. So today a typed return is quietly stored as a space, and the stored line differs from the two-line draft the user saw. Other line breaks behave differently: VT (U+000B), FF (U+000C) and NEL (U+0085) are control characters, and a pasted line containing them is rejected with "line contains disallowed characters". The client-side strip fixes both. Neither cleaner changes. They stay the hard rule, and this plan only adds input polish on top of them.

Design choices, made at Claude's discretion (this quick item has no CONTEXT.md, so this plan is the contract):
- **The mechanism is an onChange intercept, with an onSubmit backstop.** A vertical-axis TextField inserts the line break instead of calling onSubmit, so the view forwards every draft change to the model, and the model decides what the edit meant. The binding stays `$model.draft`, with no filtering custom Binding. A filtering binding that hands back an unchanged value can leave the UITextView still showing the stray line break, because SwiftUI sees no value change to push. With the intercept, the value really changes and is then cleaned, so the field redraws. `.onSubmit` also calls the same model entry point, so the behavior holds on any OS version where return calls onSubmit instead. The shared `canSubmit` gate makes a double fire send only one line.
- **A return press is an edit whose only inserted text is one line break.** Use a common-prefix/common-suffix diff over Characters, so CRLF counts as one break. A return press leaves the draft exactly as it was. That matches single-line text-field semantics, keeps any selected text, and can't add whitespace.
- **A paste never offers, even one that ends in a line break.** Offering a line is irreversible and shared with a stranger, so only an unambiguous return press may trigger it. One edge case follows from this: if autocorrect and the line break arrive as one edit, the press is read as a paste and the line is not offered. The draft keeps the corrected text plus a trailing space, and a second return offers it. That's non-destructive, and a test pins it.
- **Line breaks become spaces, not nothing.** Each run of line-break Characters becomes one space. This matches the server's own whitespace collapse, so the stored line is what the user saw, and pasted lines don't fuse ("pond\na" becomes "pond a", not "ponda"). Tabs and other non-newline whitespace are left to the cleaners (out of scope).
- **The return key is labelled send.** Change the submit label from its current value to `.send`, because the key now offers the line rather than dismissing the keyboard. This is reversible with one modifier.
- **The logic lives in the model or in a pure helper, never in the view.** This follows the PartnerPresence/StepAway pattern: `DraftInput` (a pure enum next to them in Features/Compose), plus additive `AppModel` members, tested with FakeBackend and the Rig.

Purpose: a poem line is one line. The keyboard should never let the writer build something the server will silently reshape or reject.
Output: `DraftInput.swift`, three additive AppModel members, rewired ComposeView modifiers, `ReturnKeyTests.swift` (6 tests) and `DraftInputTests.swift` (11 tests).
</objective>
