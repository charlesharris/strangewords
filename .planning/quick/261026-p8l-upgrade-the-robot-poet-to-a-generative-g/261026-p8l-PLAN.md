<objective>
Replace the robot poet's hardcoded line pools with a generative, syllable-aware composer. The new code is a stdlib-only Go package, server/internal/poet, that does five things:

- estimates syllables;
- picks one theme per poem from a seeded RNG;
- composes 5- and 7-syllable lines from grammar templates and themed word banks;
- echoes a content word from the partner's latest line (or a theme-adjacent sibling) when the syllable budget allows;
- degrades gracefully (nearest fit, then a last-resort safety net), so it never blocks and never returns an empty line.

The bot (server/cmd/bot/main.go) is rewired to use it. Only line selection changes.

Locked decision (orchestrator, not revisited): pure generative grammar in Go stdlib, with NO external AI or API calls.
Non-goals (excluded): the opt-in matchmaking flag, iOS settings UI, any wire-contract change, any edit under server/internal/gateway/ (owned by concurrent quick task 261026-p8f), any change to the iOS Syllables heuristic or its tests, and pushing to origin.

Purpose: the user wants the bot to be "more dynamic, not just the same hardcoded haikus and lines". Planning also found that two of the bot's current "5-syllable" lines actually have 6 syllables ("morning fog is lifting", "wind through the empty halls"). The curated pools drift; a counted, tested generator does not.
Output: the server/internal/poet package with tests, a rewired bot with a seam test, and a SUMMARY.
</objective>

Text handling:
- Lowercase the input.
- Delete apostrophes (ASCII ' and U+2019) so a contraction counts as one word.
- Split on every rune that is not a letter (unicode.IsLetter).
- Sum the per-word counts.

Per-word count:
- If the word is in the overrides map, return that value. The map holds true counts for words the rules miss. Seed it with poem 2, quiet 2, rhythm 2, create 2, and café 2, the known misses pinned in ios/StrangewordsTests/SyllablesTests.swift.
- Otherwise count contiguous vowel groups over "aeiouy", exactly as iOS does.
- When that count is above 1, apply at most one suffix adjustment:
  - (a) The word ends in "e": drop one, unless the word ends in "le" after a consonant (table, candle, and maple keep 2).
  - (b) The word ends in "es" and is longer than 3 letters: keep the count when it ends in "les" after a consonant (settles, candles). Otherwise drop one when the letter before "es" is a consonant that is not a sibilant. Sibilants are s, x, z, c, g, and an h preceded by c or s. So glides, fades, and lines drop; rises, dances, ashes, and branches keep.
  - (c) The word ends in "ed", is longer than 3 letters, and the letter before "ed" is a consonant other than t or d: drop one (bloomed and rained drop; folded and lifted keep).

poet.go, solver:
1. Try templates in RNG-shuffled order.
2. For each template, compute literal cost = sum of Count over its literal words.
3. Run a small depth-first search for one count per slot, chosen from that slot bank's non-empty buckets with RNG-shuffled candidate counts, so the counts sum to target minus literal cost. The first exact solution wins.
4. Fill each slot with an RNG-picked word from its bucket. Prefer words not in used, and add each placed word to used.
5. Render the article "a" as "an" before a word that starts with a vowel letter.
6. Join tokens with single spaces, all lowercase, with no leading or trailing space.

If no template solves exactly, return the last-resort safety-net line: 5 maps to "still water at dusk" and 7 maps to "the river remembers rain" (both verified at planning time). Any other target gets whichever of the two is nearer. Line must never return an empty string. Record every returned line in mine.
