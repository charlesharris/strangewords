<objective>
Make the iOS app uploadable to TestFlight with respect to two App Store Connect gates:

1. **Privacy manifest.** `TokenStore` (`ios/Strangewords/Net/Keychain.swift`) uses `UserDefaults`, which is a required-reason API. App Store Connect rejects uploads that use it without a `PrivacyInfo.xcprivacy` declaring the reason. The manifest also states the anonymity posture: no tracking, no tracking domains, no collected data types.
2. **Export compliance.** The only encryption in the app is OS-provided HTTPS through `URLSession`, which is exempt. `ITSAppUsesNonExemptEncryption: false` in the app target's Info.plist properties skips the encryption questionnaire App Store Connect otherwise asks on every build.

Purpose: remove two hard blockers on the first TestFlight upload without changing app behavior.
Output: `ios/Strangewords/PrivacyInfo.xcprivacy` (new) and an edited `ios/project.yml`. Two atomic commits. Nothing is pushed.

**Plan-time observations (live, 2026-10-26).** These authorize the scope below.
- Required-reason scan of all 28 Swift files under `ios/Strangewords`: the only family present is UserDefaults (`Net/Keychain.swift`; `App/AppModel.swift:64` mentions it only in a comment). There are zero hits for file timestamps (`creationDate`, `modificationDate`, `attributesOfItem`, `getattrlist`, `stat(`, `URLResourceKey`), system boot time (`systemUptime`, `mach_absolute_time`, `CACurrentMediaTime`), disk space (`volumeAvailableCapacity`, `NSFileSystemFreeSize`, `statfs`, `statvfs`), or active keyboards (`activeInputModes`). `ProcessInfo` is used only for `.environment`, which is not a required-reason API. There are no `.m`/`.h`/`.c` sources and no third-party SDKs.
